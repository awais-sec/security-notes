## 1. Overview of the .onion Domain

In the standard "Clear Web," domain names (like .com or .org) are managed by a central authority called ICANN and registered through commercial registrars. On the Dark Web — specifically the Tor (The Onion Router) network — domain names ending in .onion do not exist in the global Domain Name System (DNS).

Instead of being "assigned" by a company, these addresses are cryptographically generated by the server itself. This ensures that the address is tied directly to the server's identity without requiring a central registry.

## 2. Step-by-Step Generation Methodology

The creation of a .onion address follows a decentralized, mathematical process:

### A. Key Pair Generation

When a user sets up a "Hidden Service" on the Tor network, the Tor software locally generates a unique pair of cryptographic keys:
- **Private Key** — kept secret by the owner to prove ownership of the site
- **Public Key** — shared with the network to allow users to encrypt traffic sent to the site
- **Note:** modern Version 3 (v3) addresses use the Ed25519 algorithm for higher security

### B. Hashing and Encoding

The Public Key is not used as the address directly because it is too long and complex. To create the address:
1. **Hashing** — the Public Key is processed through a hashing function (SHA-3)
2. **Checksum** — a small checksum is added to the hash to detect if a user mistypes the URL
3. **Version Byte** — a specific byte is added to identify it as a "Version 3" address
4. **Base32 Encoding** — the resulting binary data is converted into a string of letters (a-z) and numbers (2-7)

### C. Final Output

The result is a 56-character string followed by `.onion`.

Example: `vww6ybal4bd7szmgncyruucpgfkqahzddi37ktceo3ah7ngmbtabcyd.onion`

## 3. Publication to the Distributed Hash Table (DHT)

Once the address is generated, the server must tell the Tor network it exists:
- The server creates a Hidden Service Descriptor, which contains its Public Key and a list of "Introduction Points" (nodes that can bridge the connection)
- This descriptor is uploaded to a Distributed Hash Table (DHT) — a decentralized "phonebook" spread across many Tor nodes
- When a user types the .onion address into a Tor browser, the browser uses the address to find the descriptor in the DHT and establish an encrypted circuit

## 4. Key Characteristics of .onion Assignments

| Feature | Description |
|---|---|
| Decentralized | No central authority can "revoke" or "suspend" a .onion name |
| Self-Authenticating | The address is the key. If you can connect to it, you are guaranteed to be talking to the owner of that specific key pair |
| Anonymity | The registration process requires no personal information, email, or payment |
| Persistence | As long as the owner has the private key, they can host the site from any computer, anywhere in the world |

## 5. Counter-Terrorism Perspective

From a counter-terrorism and digital forensics standpoint, the methodology of .onion assignment presents unique challenges:

- **Attribution** — because there is no "WHOIS" data, investigators cannot simply look up who registered a domain
- **Takedowns** — traditional domain seizing (redirecting a URL to a law enforcement splash page) is impossible without obtaining the server's physical private key
- **Vanity Addresses** — terrorist organizations often use "vanity miners" to generate addresses that start with specific words to make their links more recognizable to recruits, despite the random nature of the generation process
