# Project Management and SDLC

## Project Roles and Responsibilities

- **Project**: A structured set of activities delivering a defined capability to the enterprise, on an agreed schedule and budget.
- **Project portfolio**: The full set of projects a company owns, including objectives, costs, timelines, and other specifics.
- **PERT (Program Evaluation and Review Technique)**: A project management technique used in planning and controlling system projects.

### Projects vs. Programs

- **Project**: Specific objectives and deliverables, defined start/end dates, always time-bound, usually broken into explicit phases.
- **Program**: A group of projects and time-based tasks linked by a common objective, generally more complex, longer duration, higher budget and risk, and higher strategic importance.

### Project management processes

Initiating, Planning, Executing, Controlling, Closing.

### Project context

- Importance of the project within the organization
- Connection between organizational strategy and the project
- Relationship between the project and other projects
- Connection between the project and the underlying business case

### Project organization types

- **Influence project organization**: Project manager has only a staff function, no formal management authority.
- **Pure project organization**: Project manager has formal authority over project participants.
- **Matrix project organization**: Management authority is shared between the project manager and department heads.

### Roles and responsibilities

Senior management, user management, project steering committee, project sponsor, project manager, systems development management and project team, user project team, security officer/information system security engineer, quality assurance.

### Project communication

Communicated through one-on-one meetings, kick-off meetings, project start workshops, or a combination of these. Should always be open, clearly presented, and documented.

### Project culture

Made up of the shared norms, beliefs, values, and assumptions of the project team, defined through things like a mission statement, project name/logo, project office or meeting place, communication protocols, and a project intranet.

### Project objectives

Specific action statements supporting the project's goals, should always start with an action verb, and follow **SMART**: Specific, Measurable, Attainable, Realistic, Timely.

- **Object Breakdown Structure (OBS)**: Represents the individual components of the solution and their hierarchical relationship.
- **Work Breakdown Structure (WBS)**: Lists every necessary task, grouped into manageable and controllable units.

Project management is a risk-based, iterative process by nature.

### IS auditor's role in project management

Review the adequacy of project management activities: oversight, risk management, issue management, cost management, planning and dependency management, reporting processes, change control processes, stakeholder management involvement, and the sign-off process.

## SDLC (System Development Life Cycle)

The process used to plan, design, develop, test, and implement an application system, or a major modification to one.

### SDLC models

- **Traditional Waterfall**: Linear and sequential, with formal sign-off at each level.
- **V-shaped**: Similar to waterfall, but focused on verification and validation.
- **Iterative**: Repeating cycles of development and refinement.

### Phases of SDLC

1. **Feasibility Study**: Determine whether the project is viable and worth pursuing, by analyzing costs, benefits, and risks.
2. **Requirements Definition**: Identify what the system should do; gather and document user needs and system requirements.
3. **Software Selection and Acquisition**: Choose or develop the right software, evaluating options and selecting or planning custom development.
4. **Design**: Plan how the system will work, creating detailed designs for components, interfaces, and data.
5. **Configuration and Development**: Build the system, configure software, write code, and develop components.
6. **Final Testing and Implementation**: Ensure the system works correctly and is ready for use, testing thoroughly, fixing issues, and deploying.
7. **Post-Implementation Review**: Evaluate the system after it's live, reviewing performance, gathering feedback, and making improvements.

### Key success factors

Productivity, quality, economic value, customer service.

### IS auditor's role in SDLC

Documentation review (ensuring all phases are well-documented), meeting attendance (participating to advise), and deliverable assessment (checking key deliverables are produced on time).

## Testing Technologies (Methodologies)

Testing methodology refers to the strategies and processes used to confirm software functions correctly and meets specified requirements, identifying and fixing defects along the way.

### Main types

- **Unit Testing**: Tests individual components or modules for correctness.
- **Integration Testing**: Evaluates how integrated components interact.
- **System Testing**: Assesses the complete system's compliance with requirements.
- **Acceptance Testing**: Confirms the system meets user needs and is ready for deployment.

### Other types

- **Alpha Testing**: Performed by users within the organization developing the software.
- **Beta Testing**: Involves a limited number of external users, with real-world exposure.
- **Pilot Testing**: Focuses on specific, predetermined aspects of a system, such as a proof of concept.
- **White Box Testing**: Uses knowledge of the program/module's underlying implementation and code to verify expected behavior.
- **Black Box Testing**: Focuses on functionality without requiring knowledge of the underlying code.
