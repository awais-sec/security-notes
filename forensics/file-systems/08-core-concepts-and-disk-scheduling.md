# Core File System Concepts and Disk Scheduling

Exam-prep notes split into short definitional questions and longer conceptual questions.

## Short Questions (Definitions & Concepts)

**External Fragmentation**

Occurs when free memory is split into small non-contiguous chunks, making it hard to allocate large files without rearranging existing ones. This leads to wasted memory and poor efficiency.

**File System**

A file system is how an operating system organizes, manages, and retrieves data from storage devices. Think of it as a digital library system — tracking where each "book" (file) is, how it's accessed, and who can use it.

**Chain of Custody**

The Chain of Custody is the documented process of handling evidence — from collection to courtroom. It records who handled the evidence, when, where, and why, ensuring the integrity and credibility of digital evidence.

**File Attributes**

These are metadata properties that define a file's behavior in the OS. Common attributes include:

- Read-only
- Hidden
- System
- Archive

**Slack Space**

When a file doesn't fully occupy the allocated storage block, the leftover space is called slack space. This area may still contain residual data from deleted files — potentially a goldmine in digital forensics.

**File Allocation Method**

Refers to how a file system stores file data on a disk. Examples:

- Contiguous
- Linked
- Indexed

These methods define how files are arranged and accessed.

**File Operations**

Examples include Create and Write. Other operations: Read, Open, Close, Delete, Seek, Truncate.

**Linked Allocation**

Files are stored as a linked list of blocks. Each block contains a pointer to the next, which eliminates the need for contiguous space and reduces fragmentation — but hinders random access.

**Digital Forensics**

A branch of forensic science focused on identifying, preserving, analyzing, and presenting digital evidence from electronic devices. Crucial for tackling cybercrimes, fraud, and data breaches.

**Internal Fragmentation**

In linked allocation, if a file doesn't fully occupy the last block, the remaining space is wasted — this is internal fragmentation.

**Directories**

Directories (or folders) organize files in a hierarchical structure. They act as containers and help the OS track, access, and manage files efficiently.

**Levels of Directories**

1. **Single-Level**: one directory for all files.
2. **Hierarchical**: tree-like structure with nested folders.

**FAT (File Allocation Table)**

An older file system used in Windows and removable drives. It tracks file fragments using a table, showing which clusters belong to which files. It lacks modern features like permissions and journaling.

**NTFS (New Technology File System)**

Used in Windows, NTFS stores file data and metadata in a Master File Table (MFT). It supports advanced features:

- File permissions
- Compression
- Encryption
- Journaling

**Logical vs. Physical Address**

- **Logical Address**: virtual memory location generated by the CPU.
- **Physical Address**: actual address in RAM or disk where data is stored.

**NAS (Network-Attached Storage)**

A device connected to a network that provides shared file-level storage to multiple users. Uses protocols like NFS or SMB for easy access — ideal for backups and collaboration.

**Seek Time**

Also called positioning time, it's the delay for the hard disk's read/write head to move to the correct track. It's one of the slowest components of data retrieval. Disk scheduling algorithms help reduce seek time.

## Long Questions

### File Allocation Methods

**Contiguous Allocation**

Allocates consecutive blocks of storage at file creation.

- *Pros*: easy to implement, fast access (especially for sequential files), supports direct access.
- *Cons*: external fragmentation, file size must be known upfront, large files may not find free contiguous space.

**Linked Allocation**

Allocates blocks non-contiguously; each block has a pointer to the next.

- *Pros*: no external fragmentation, flexible size management, simple directory entries.
- *Cons*: slower access (no direct access), pointer overhead in each block, internal fragmentation possible in the last block.

### Disk Scheduling Algorithms

Disk scheduling determines the order of disk I/O requests for better performance.

**FCFS (First Come, First Served)**

- Processes requests in arrival order.
- Simple but may result in long seek times.

**SSTF (Shortest Seek Time First)**

- Prioritizes the request closest to the current head position.
- Reduces access time but may cause starvation.

**SCAN (Elevator Algorithm)**

- Disk head moves in one direction, serving requests, then reverses.
- Balanced but can still waste time reaching disk ends.

**C-SCAN (Circular SCAN)**

- Only scans in one direction, then returns quickly to the start.
- Better response time uniformity.

**LOOK and C-LOOK**

- Like SCAN and C-SCAN but stop at the last request instead of going to disk edges.
- Saves time and prevents unnecessary head movement.
