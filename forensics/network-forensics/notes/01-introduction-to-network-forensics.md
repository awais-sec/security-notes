# Introduction to Network Forensics

## Why Network Forensics?

- Attackers breach the security framework of any organization and gain unauthorized access to its confidential/sensitive data through network infiltration.
- Conventional network defense mechanisms are important and, to some extent, can deter attackers, but they are not infallible.
- It's essential for businesses to recognize the signs of a network attack, identify the defenses or security policies that were breached, and adopt measures to safeguard their network resources.
- Network forensic investigation refers to the analysis of network security events (which include network attacks and other undesirable events) for two broad purposes:
  - To determine the causes of the network security events so that appropriate safeguards and countermeasures can be adopted.
  - To gather evidence against the perpetrators of the attack for presentation in the court of law.

## Introduction to Network Forensics

- Part of digital forensics: involves the investigation of cybercrimes occurring at the network level.
- Network forensics entails probing into various network-based sources of evidence to identify anomalies or breaches.
- Forensic investigators deal with a large amount of dynamic information to trace accurate sources of network security incidents and present them as evidence in the court of law.
- **Definition**: network forensics is the capturing, recording, and analysis of network events to discover the source of security incidents.
- **Challenges in capturing**: complicated in practice due to many inherent factors such as the large amount of data flow and the complex nature of Internet protocols.
- **Analysis**: investigators use many manual as well as automated analysis tools and methods to detect malicious activities within the network.
- **Reveals**: source of security incidents, the path of intrusion, intrusion techniques an attacker used, traces and evidence.
- **Involves**: sniffing, capturing, and analyzing network traffic and event logs to investigate a network security incident.
- Helps investigators determine the type of attack over a network and trace the perpetrators. A proper investigation process can help investigators produce potential evidence to submit in the court of law.
- Cyber-attacks may not be manifested until a major impact is noticed on the network resources. Network forensics helps not only detect malicious activities but also helps reduce the impact of similar incidents in the future.
- The analysis of recorded data is the most critical and time-consuming task. There are many automated analysis tools for forensic purposes, but they are insufficient, as there is no foolproof method to recognize malicious traffic generated by an attacker from a pool of genuine traffic. Human judgment is also critical, because automated traffic analysis tools may produce false-positive results.
- **Preparation**: steps can be taken in advance to ensure network forensics readiness, such as establishing suitable event logging and data collection mechanisms that can provide key artifacts for analysis during a forensic investigation.

## Postmortem and Real-Time Analysis

Forensic examination of logs can be divided into two categories:

**1. Postmortem**

- Conducted to investigate an incident that has already happened.
- Investigators perform a postmortem analysis to detect and study incidents that have already taken place in a network, which helps them determine what exactly occurred and the accurate source of the event. It involves blame-free examination and discussions initiated immediately after the occurrence of an event.
- An artifact is created that contains details about the exact cause of the incident and a set of actions necessary to ensure that something similar does not take place in the future.
- An investigator can examine the log files several times to analyze and verify the sequence of events that led to the incident. Compared to real-time analysis, it's an exhaustive process, since the investigators need to examine the attack in detail and give a final report.

**2. Real-Time**

- Conducted to detect and examine an ongoing attack.
- Performed during an ongoing attack, with results generated simultaneously, making it easier to respond to attacks immediately.
- Investigators can gain a deeper understanding of the traffic flowing across their network with this type of analysis. Real-time traffic analysis can also enable investigators to gain situational awareness and differentiate legitimate and deviating traffic patterns.
- Such analysis is more effective if the investigator is skilled enough to detect the attack quickly. Unlike in postmortem analysis, the investigator can examine the log files only once, as time plays a crucial role in real-time analysis.

## Network Attacks

Aimed at compromising network security through active and passive means. Network-based attacks can range from mere sniffing to injecting deadly malware into the organization's security infrastructure.

**Most common attacks on networks**

- **Eavesdropping**: a technique used to intercept unsecured connections to steal personal information.
- **Data Modification**: intruder alters/deletes sensitive data.
- **IP Address Spoofing**: attacker accesses a computer without authorization by sending messages from a trusted host's IP.
- **Denial-of-Service (DoS)**: floods target with invalid traffic, exhausting resources and causing denial of service for legitimate users.
- **Man-in-the-Middle Attack**: eavesdropping where the attacker establishes independent connections, tricking users into thinking they're communicating directly.
- **Packet Sniffing**: captures network traffic to obtain sensitive info (usernames/passwords) using sniffers like Cain & Abel.
- **Enumeration**: gathers network info (topology, live hosts, traffic type, vulnerabilities) for attacks, often over the Internet.
- **Session Hijacking**: exploits session-token generation to establish an unauthorized connection with a target server.
- **Buffer Overflow**: exceeds buffer capacity, overflowing into neighboring buffers and destroying/overwriting data.
- **Email Infection**: uses emails for network attacks/DoS via spamming.
- **Malware Attacks**: malicious code/software used to infect/affect systems or performance, damaging once installed.
- **Password-Based Attacks**: repeated login attempts with password combinations to mimic legitimate login.
- **Router Attacks**: compromises a router to gain access.

**Attacks specific to wireless networks**

- **Rogue Access Point Attack**: a rogue AP in an 802.11 network hijacks connections; a user's NIC connects to it, passing traffic through for sniffing.
- **Client Misassociation**: a client connects to a neighboring misconfigured AP due to various reasons (coverage, policy, etc.), without the client's or rogue AP's knowledge.
- **Misconfigured Access Point Attack**: misconfiguration exploits entire network vulnerabilities/attacks.
- **Unauthorized Association**: malicious or accidental; attacker uses a soft AP (laptop) to gain network access.
- **Ad Hoc Connection Attack**: direct Wi-Fi client communication without an AP; insecure, and an attacker can force ad-hoc mode to compromise the wired LAN.
- **Honeypot Access Point Attack**: a rogue AP with the same SSID as a legitimate one, with a stronger signal to attract clients and reveal sensitive info.
- **Key Reinstallation Attack (KRACK)**: exploits WPA2 flaws in the four-way handshake to establish a connection/generate an encryption key.
- **Access Point MAC Spoofing**: spoofs an AP's MAC/SSID via beacons; clients connect, and the attacker gains full access if MAC filtering is used.
- **Jamming Signal Attack**: overwhelms with malicious traffic, causing denial of service to authorized users and blocking communications completely.

## Indicators of Compromise (IoCs)

Evidence items pointing to security violations on a host/network. When an incident occurs, trace activities in the affected system/logs, looking for signs like sudden outbound traffic spikes or unusual logins.

**Examples**

1. Unusual outbound network traffic (sign of ongoing attack).
2. Increase in failed login attempts.
3. Increased requests for the same file.
4. Network traffic on unusual ports.
5. Unknown connections in the network.
6. Protocol violations (e.g., SSL/TLS when attackers access networks).
7. File modification.
8. Increased bandwidth consumption (uploading/downloading malicious content).
9. Unexpected system/server reboot (malware/unauthorized install).
10. Service unavailability (DoS/DDoS sign).
11. Logins from unknown locations (abnormal times/unusual/multiple).
12. Unknown configuration changes (unauthorized in network services).

Other IoC signals: malicious URLs spread via phishing/spamming, user-agent strings (inform the server of a device's OS/browser), and alerts from system-based security solutions.

## Where to Look for Evidence

Logs from network devices and applications serve as evidence for incidents. Analyze logs to trace events; for security events, traces are likely in logs from one or more network layers. Understanding these layers requires the TCP/IP or OSI models.

**TCP/IP Model Layers**

- **Network Access Layer** (bottom): defines network use for data transfer. Protocols: Frame Relay, SMDS, Fast Ethernet, SLIP, PPP, FDDI, ATM, Ethernet, ARP, Proxy ARP, RARP.
- **Internet Layer**: handles packet movement from source to destination. Protocols: IP, ICMP, ARP, IGMP.
- **Transport Layer**: backbone for data flow between devices, enabling peer communication. Protocols: TCP (reliable), UDP (non-reliable).
- **Application Layer** (top): uses the transport layer to deliver data. Protocols: HTTP, Telnet, FTP, SMTP, NFS, TFTP, SNMP, DNS.

**OSI Model vs. TCP/IP**

- OSI has 7 layers: Application, Presentation, Session, Transport, Network, Data Link, Physical.
- TCP/IP has 4: Application (combines OSI Application/Presentation/Session), Transport, Internet, Network Access (combines OSI Data Link/Physical).

**Network devices and logs**: servers/desktops, anti-virus, business applications, databases; firewall, IDS/IPS, VPN; routers and switches.

## Types of Network-Based Evidence

The ultimate goal is to gather admissible evidence for court.

- **Full Content Data**: actual packets captured/stored (known as pcap files). Tools: tcpdump, Wireshark to analyze subsets.
- **Session Data**: summary of conversations between network entities. Includes destination IP/port, source IP/port, start time, session duration, and info exchanged.
- **Alert Data**: triggered by tools like Snort IDS or Suricata. Preprogrammed to examine traffic for IoCs and report findings — be careful with false positives.
- **Statistical Data**: overall profile/summary of network traffic. Yields info like timestamps for conversations, protocols/services used, average packet size, and average packet rate.
